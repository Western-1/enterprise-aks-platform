# Architecture — Enterprise AKS Platform

[Українська версія](architecture.ua.md)

## Overview

The platform is a single-tenant dev environment in Azure. All infrastructure is
declared in Terraform, all applications are delivered by Argo CD from a GitOps
repository, and workloads authenticate to Azure without any secrets in code.

## Components

### Azure layer

| Component | Name | Purpose |
|---|---|---|
| Resource group | `rg-dev-aks-ne` | Single RG for the whole environment |
| Virtual network | `vnet-dev-aks-ne` (10.0.0.0/16) | Everything lives inside this VNet |
| Subnets | `snet-aks` (10.0.1.0/24), `snet-app` (10.0.2.0/24), `snet-private-endpoint` (10.0.3.0/24) | Network isolation |
| NSGs | `nsg-aks`, `nsg-app`, `nsg-private-endpoint` | Per-subnet firewall (rules to be refined) |
| ACR | `acrdevmedia` (Basic) | Container images; admin disabled |
| Key Vault | `kv-dev-media-ne` | All secrets; private endpoint; RBAC |
| AKS | `aks-dev-cluster-ne` (1.34) | The Kubernetes cluster |
| Log Analytics | `la-dev-aks-ne` | Container insights, metrics, logs |
| PostgreSQL | `psql-dev-media-ne` (PG16, B1ms) | Database; private endpoint only |

### AKS internals

- **Networking**: Azure CNI Overlay + **Cilium** dataplane (Cilium also enforces NetworkPolicies).
- **Node pools**:
  - `system` — 2 × `Standard_EC2as_v5` (confidential compute, the only family the trial allows), Azure Linux.
  - `user` — 0–1 × `Standard_EC2as_v5`, autoscaled, for application workloads.
- **Identity**: System-assigned cluster identity + **OIDC issuer** + **Workload Identity** for pods.
- **Security**: Azure Policy (Gatekeeper), Secrets Store CSI driver with rotation, API server IP allowlist.
- **Scaling**: node-pool autoscaler on both pools; HPA for pods (to be added with the app).

### Secrets flow (Zero Trust)

```
PostgreSQL password
        generated by Terraform (random_password)
                  │
                  ▼
          Key Vault  db-password / db-url
                  │
     (pod) CSI driver ← Workload Identity ← service account
                  │
                  ▼
            application reads secret
```

No password ever appears in a git repository or a Kubernetes manifest.

### Network topology

```
                   10.0.1.0/24 snet-aks      AKS nodes + pods
VNet 10.0.0.0/16   10.0.2.0/24 snet-app       future app-gateway / jumpbox
                   10.0.3.0/24 snet-private-endpoint   PE: KV, PostgreSQL

Private DNS zones: privatelink.vaultcore.azure.net, privatelink.postgres.database.azure.com
```

Key Vault and PostgreSQL are reachable **only** through private endpoints — no public IPs.

## GitOps delivery

```
developer: git push
     │
     ▼
enterprise-aks-gitops repo (single source of truth)
     │  Argo CD polls (app-of-apps)
     ▼
AKS cluster converges (Sync/Healthy)
```

- **Root application** `app-of-apps` watches `infrastructure/argocd/` in the GitOps repo
  and creates every `Application` declared there.
- **cluster-config** applies cluster-level manifests: namespaces (`media`, `database`,
  `monitoring`, `ingress`), `ResourceQuota`, `LimitRange`.
- Nothing is applied with `kubectl apply` — Argo CD is the only writer.
