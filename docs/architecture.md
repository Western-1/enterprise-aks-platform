## Overview

The platform is a single-tenant dev environment in Azure. All infrastructure is
declared in Terraform, all applications are delivered by Argo CD from a GitOps
repository, and workloads authenticate to Azure without any secrets in code.

## Components

### Azure layer

| Component | Name | Purpose |
|---|---|---|
| Resource group | `rg-dev-aks-ne` | Single RG for the whole environment |
| Virtual network | `vnet-dev-aks-ne` (10.0.0.0/16) | Everything lives inside this VNet |
| Subnets | `snet-aks` (10.0.1.0/24), `snet-app` (10.0.2.0/24), `snet-private-endpoint` (10.0.3.0/24) | Network isolation |
| NSGs | `nsg-aks`, `nsg-app`, `nsg-private-endpoint` | Per-subnet firewall (rules to be refined) |
| ACR | `acrdevmedia` (Basic) | Container images; admin disabled |
| Key Vault | `kv-dev-media-ne` | All secrets; private endpoint; RBAC |
| AKS | `aks-dev-cluster-ne` (1.34) | The Kubernetes cluster |
| Log Analytics | `la-dev-aks-ne` | Container insights, metrics, logs |
| PostgreSQL | `psql-dev-media-ne` (PG16, B1ms) | Database; private endpoint only |

### AKS internals

- **Networking**: Azure CNI Overlay + **Cilium** dataplane (Cilium also enforces NetworkPolicies).
- **Node pools**:
  - `system` — 2 × `Standard_EC2as_v5` (confidential compute, the only family the trial allows), Azure Linux.
  - `user` — 0–1 × `Standard_EC2as_v5`, autoscaled, for application workloads.
- **Identity**: System-assigned cluster identity + **OIDC issuer** + **Workload Identity** for pods.
- **Security**: Azure Policy (Gatekeeper), Secrets Store CSI driver with rotation, API server IP allowlist.
- **Scaling**: node-pool autoscaler on both pools; HPA on `media-api` (live).

### Secrets flow (Zero Trust)

```
PostgreSQL password
        generated by Terraform (random_password)
                  │
                  ▼
          Key Vault  db-password / db-url
                  │
     (pod) CSI driver ← Workload Identity ← service account
                  │
                  ▼
            application reads secret
```

No password ever appears in a git repository or a Kubernetes manifest.

### Passwordless PostgreSQL (Microsoft Entra ID)

The demo app does not use the Key Vault password at all. Instead, the pod's
workload identity (`uami-media-dev-ne`, registered as the server's Entra
administrator) fetches a short-lived access token and passes it as the
PostgreSQL password:

```
pod (service account media-api)
  │  federated credential → workload identity (client-id 2308ae95-…)
  ▼
login.microsoftonline.com → token for https://ossrdbms-aad.database.windows.net
  │  (scope ossrdbms-aad — the legacy ossrdbms scope is rejected with AADSTS500011)
  ▼
psql-dev-media-ne.postgres.database.azure.com as uami-media-dev-ne (ssl=require)
```

- Network: the `default-deny` policy blocks everything; `allow-db-egress` opens
  `10.0.3.0/24:5432` and `allow-aad-egress` opens TCP 443 for the token endpoint.
- The `db-init` job creates the `media` database with the same identity before the app starts.
- No passwords anywhere: the legacy Key Vault secrets (`db-password` / `db-url`)
  and the CSI driver mounts were deleted — the random admin password exists only
  because Azure requires it at server creation (break-glass via Terraform state).

### Network topology

```
                   10.0.1.0/24 snet-aks      AKS nodes + pods
VNet 10.0.0.0/16   10.0.2.0/24 snet-app       future app-gateway / jumpbox
                   10.0.3.0/24 snet-private-endpoint   PE: KV, PostgreSQL

Private DNS zones: privatelink.vaultcore.azure.net, privatelink.postgres.database.azure.com
```

Key Vault and PostgreSQL are reachable **only** through private endpoints — no public IPs.

## Observability (live)

- `kube-prometheus-stack` 90.0.0 via Argo CD (`monitoring` app, multi-source:
  chart from the public repo + `apps/monitoring/values.yaml` from GitOps).
  Tuned for the small nodes: 7d/8GB retention, 10Gi PVC, alertmanager off,
  Grafana ClusterIP with 5Gi persistence (admin password generated by the chart,
  read it from the `monitoring-grafana` secret).
- `media-api` exposes `/metrics` (`media_items_created_total` counter) and a
  `ServiceMonitor` feeds it to Prometheus — verified end to end.
- Redis runs as an in-cluster `Deployment` in `media` (no Azure Cache for Redis
  was ever created) — the queue between `media-api` and `media-worker`.
- Grafana stays private (no extra LB frontend): check from inside the cluster.
- Tempo 1.24 (single binary, 5Gi PVC) + OTel collector (deployment) in the same
  namespace: `media-api` exports FastAPI + asyncpg spans over OTLP/HTTP
  (`OTEL_EXPORTER_OTLP_ENDPOINT`, allowed by the `allow-otlp-egress` policy),
  the collector batches them into Tempo; Grafana has Tempo as a datasource.
- Two Argo CD lessons from this rollout: the prometheus-operator CRDs exceed the
  256KB annotation limit under client-side apply → `ServerSideApply=true`;
  Argo 2.14 client schema does not know `.status.terminatingReplicas` (newer K8s)
  → server-side diff compare option on the app.

## GitOps delivery

```
developer: git push
     │
     ▼
enterprise-aks-gitops repo (single source of truth)
     │  Argo CD polls (app-of-apps)
     ▼
AKS cluster converges (Sync/Healthy)
```

- **Root application** `app-of-apps` watches `infrastructure/argocd/` in the GitOps repo
  and creates every `Application` declared there.
- **cluster-config** applies cluster-level manifests: namespaces (`media`, `database`,
  `monitoring`, `ingress`), `ResourceQuota`, `LimitRange`.
- Nothing is applied with `kubectl apply` — Argo CD is the only writer.

### External access (last live state: ingress)

- Final setup: `ingress-nginx` on the cluster outbound LB frontend `4.210.50.215`,
  nip.io hosts, self-signed demo TLS (`selfsigned-demo` ClusterIssuer —
  Let's Encrypt HTTP-01 was abandoned: no Azure LB hairpin for the self-check).
  - Demo API: `https://media.4-210-50-215.nip.io` (verified: `/healthz` ok,
    POST creates items).
  - Argo CD UI kept the original `LoadBalancer` service (`http://20.54.22.159`,
    `server.insecure: true`); an HTTPS ingress
    (`https://argocd.4-210-50-215.nip.io`) was committed to GitOps but never
    verified live — the cluster died first.
- Earlier iteration used one LB service per app (`media-api-lb` on `:8080`,
  old IP `4.245.138.35`); replaced by ingress to save frontend IPs (the trial
  subscription allows only 3 public IPs).
- `nsg-aks` allows TCP 80/443 from the Internet for LB frontends (`lb_ingress_ports`
  in the networking module) — everything else stays denied (zero-trust posture).
- Why not `kubectl port-forward`: the Cilium datapath on AKS intercepts only the nodePort
  range on node IPs, while the Azure LB rule targets the service port (floating IP).
  A LoadBalancer service is the supported access path.
